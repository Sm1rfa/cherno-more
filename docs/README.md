# Docs

Documentation, plans, and schema notes for `cherno-more-pwa`, kept next to the code so context isn't lost between sessions.

- [`api-reference.md`](./api-reference.md) — the canonical data schema the app uses internally, how it maps to each provider's real response shape, and how caching/fallback works. Read this before touching `src/api/`.
- [`../public/data/README.md`](../public/data/README.md) — if you just want to update fixtures/standings/squad content, start there instead — it's the quick "what do I type" reference for those JSON files.
- [`sportscore-openapi.yaml`](./sportscore-openapi.yaml) — the primary live provider's own OpenAPI spec, kept for reference alongside `api-reference.md`'s SportScore section.
- [`plans/`](./plans/) — point-in-time implementation plans, kept as a record of *why* something was built a certain way. Not living documentation — see `api-reference.md` for the current state of things. Start with the [pivot](./plans/2026-08-goalbg-only-pivot.md) if you're wondering why there's no api-football code despite the earlier [migration plan](./plans/2026-08-api-football-migration.md); see [data sources declined](./plans/2026-08-data-sources-declined.md) if you're wondering why there's no bulgarian-football.com scraper, [SportScore integration](./plans/2026-08-sportscore-integration.md) for why there's a "Powered by SportScore" link in the header, [history data shaping](./plans/2026-08-history-data-shaping.md) for why the History tab has full match events but no lineups, and [live match & push](./plans/2026-08-live-match-and-push.md) for the live-polling/lineups/Web-Push build (`public/push/`, `src/sw.ts`, `src/hooks/useLiveMatch.ts`) plus two real bugs it caught (SPA navigation swallowing `/push/*`, reversed scores on away matches).
